Social publishing with a built-in MCP server

One place to publish, for you and your AI agents.

SocialOS connects your social accounts, lets you write a post once, tailor it per platform and schedule it. The same abilities are available to AI agents through an MCP server, with scoped, revocable keys.

Try the demo Read the docs

The demo is the real app running in your browser. No sign-up, and your data stays on your device.

How it works

Three steps from a blank screen to a post going out on schedule.

  1. Connect your accounts

    LinkedIn through OAuth. Telegram channels and groups by posting a one-time code in the chat, which proves you control it. Tokens are encrypted at rest.

  2. Compose once, schedule per platform

    Write the post, tailor the text for each network, check the previews, then publish or schedule. A worker publishes on time and retries transient failures without ever posting twice.

  3. Let agents help, within limits

    Create an MCP connection, tick the permissions you are comfortable with and paste the config into your agent. It can draft and schedule; anything risky needs an explicit confirmation.

Supported networks

Two networks work today. The rest are registered but disabled, because each needs platform approval or a business account.

NetworkStatusWhat works
LinkedIn Live Personal profiles through OAuth 2.0. Text and images. Company pages need Marketing Developer Platform approval from LinkedIn; video is not supported yet.
Telegram Live Channels and groups through the Bot API. Text, images, video and delete. Connected by posting a one-time code, never by typing a channel name.
Instagram, Facebook, TikTok, YouTube, X, Threads, Pinterest Not available yet Registered as stubs that answer PROVIDER_NOT_AVAILABLE. They are not pretended to work.
Mock network Development only A deterministic provider for tests and the demo. Refused when the server runs in production mode.

"Live" means the adapter talks to the real API and is tested against fakes of it. You bring your own LinkedIn app and Telegram bot; see provider setup.

An MCP server with a leash

Agents such as Claude Desktop connect through the Model Context Protocol and use the same REST API as the app, with the caller's own key. The MCP server holds no state and no social credentials, so it can never bypass authorization.

Permission model

  • Scoped keys. Nine scopes. Tools a key has no scope for are not even listed, and the REST API checks the scope again on every call.
  • Dangerous actions are opt-in. publish_post, delete_post and disconnect_account are off by default and need confirm: true on every call.
  • Revocable and expiring. Keys are stored as SHA-256 hashes and shown once. Revoking a connection invalidates its key immediately.
  • Audited. Every agent action lands in the audit log as api_key:<name>. Keys can never create keys or change account security.

Connect an agent

Create a connection under Developer, then paste the generated config. For example, for an HTTP client:

{
  "mcpServers": {
    "socialos": {
      "type": "http",
      "url": "http://localhost:3333/mcp",
      "headers": { "Authorization": "Bearer sk_live_..." }
    }
  }
}

Built so a post goes out once

At most one publish per target

Each target carries an idempotency key. If a worker crashes between the network call and the database write, the target becomes needs_review instead of being posted again. A visible miss beats a duplicate.

Retries only where they are safe

Network errors, 5xx responses and rate limits back off exponentially, up to five attempts. Permanent and authorization errors fail visibly, with the reason attached to the attempt.

Secrets stay secret

OAuth tokens are encrypted with AES-256-GCM and never logged. Browser sessions are opaque server-side sessions with CSRF protection. Every query is scoped to its owner.

A scheduler you can reason about

The database is the source of truth and Redis only carries jobs. A reconciler re-enqueues anything that is due but missing, so a Redis flush does not lose scheduled posts.

Run it yourself

SocialOS is self-hosted. One command starts Postgres, Redis, MinIO, the API, the worker, the MCP server and the web app. With the mock network enabled you can try the whole flow without any credentials.

make up        # generates .env, then docker compose up
open http://localhost:3000

Local setup, environment variables, OAuth setup and the full API are in the documentation.
